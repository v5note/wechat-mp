# 事实核查（fact-check）

公众号内容一旦发出就会被人当真。**涉及具体产品、版本、价格、数据、事件、人物、奖项、融资、发布时间，先核实再写。**

## 什么时候必须查

- 介绍某个真实产品 / 开源项目 / 公司：版本号、Star 数、License、功能是否已发布。
- 引用数据：用户量、增长率、性能数字、价格、排名。
- 引用评价 / 名人名言 / 获奖情况。
- 时间敏感信息：发布日期、是否「刚刚」「今天」。

## 步骤

1. **先搜**：用 WebSearch 查官方文档、官网、发布说明、GitHub release、权威媒体。至少两个来源交叉。
2. **落档**：把结论写进项目根目录的 `facts.md`，每条注明来源 URL 和检索日期。
3. **搜不到就问**：向用户确认，或标注「待确认」，**不要编**。
4. **写进正文**：只写有来源的事实；推测用「据官方」「约」「截至 X 月」限定。

## facts.md 模板

```md
# 事实核查 · <项目名>

| 事实 | 值 | 来源 | 检索日期 |
|---|---|---|---|
| 最新版本 | v1.2.0 | https://github.com/.../releases | 2026-11-16 |
| Star 数 | 17.6k | GitHub 仓库页 | 2026-11-16 |
| License | MIT | LICENSE 文件 | 2026-11-16 |

## 待确认
- 融资轮次（未找到可靠来源，正文不写）
```

## 红线

- **不编造**统计数字、用户评价、名人名言、logo 墙、奖项。
- **不写过期**版本号/价格；不确定就写「以官网为准」。
- 演示用的虚构数据必须显式声明「仅为演示」，且不能伪装成真实品牌。
- 找不到官方素材时，用诚实的占位（灰块 +「示意图」），不要画一个假 logo。
