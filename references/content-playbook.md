# 文案手册（content-playbook）

标题、摘要、导语、小标题、卡片文案、CTA 的写法与四类体裁大纲。目标是「有钩子但不标题党、信息密度高但读得动」。

## 1. 标题公式（文章 3–5 条，贴图 2–3 条）

微信标题在信息流只露出前 ~20 字，**把钩子放最前**，用具体名词与数字，少用形容词。

- **数字 + 结果**：27 张支付架构图，我本来舍不得发
- **反常识 / 转折**：放弃了若依，我选择了它
- **痛点 + 解法**：C 盘又满了？这次我只说了几句话
- **身份 + 场景**：做 Java 后台，先别急着上微服务
- **教程承诺**：照着点就行：10 亿 Token 四步领到手
- **对比选型**：Rust 版若依值得用吗？先说真实边界

贴图标题 = 一张封面的主标题，≤20 字，两行内，一句结论。

**自检**：能否一句话说清「给谁、解决什么、得到什么」？不能就重写。标题不夸大、不用「震惊/必看/史上最」。

## 2. 摘要（≤54 字）

公式：**对象 + 价值 + 一个具体锚点**。独立成立，不重复标题原句，不写「本文将介绍…」。

例：把 27 张支付架构图整理成一册：收银台、交易、清结算、对账全链路，附下载。

## 3. 导语公式（3–5 句）

开头直接上冲突，别铺垫。四种开场任选：
1. **痛点场景**：先还原读者此刻的窘境。
2. **结论先行**：一句话给答案，再解释。
3. **具体数字**：用真实数字/结果抓住注意。
4. **亲历口吻**：「我用了两周，发现…」。

导语结尾留一句「本文解决 X」，把读者带进正文。

## 4. 小标题（节标题）

- 结论式优于名词式：二、真正拖慢你的不是数据量，是索引 好过 二、性能优化。
- 每节只解决一个问题；节与节之间有递进或并列关系。
- 编号全文统一（一、二、三 或 01 02 03）。

## 5. 卡片文案（贴图）

- **封面**：主标题两行、副标题一行、2–3 个卖点标签 + 首屏预览缩略（后面 3–4 张卡的关键词）。主标题要有落差或结果感，
  第一行就交代「结果/反常识」，第二行交代「对象」；标题写完回头默读一遍——**没读过正文的人只看这张卡，能不能听懂一句结论**。
  预览缩略图每格只写关键词（≤8 字），不写句子，否则在小尺寸下糊成一片。
- **要点卡**：标题 ≤14 字结论句 + 正文 ≤60 字。
- **图解卡**：标题一句「怎么运作」；图注一句小结。
- **对比卡**：维度名短，左右各一句短语 + ✓/✗。
- **结尾卡**：3–5 条回顾 + 一句 CTA；推荐加 2–3 条「下期预告」，和首图的「往下还有」首尾呼应。
- **手机卡**：标题 ≤8 字/行 + 3 条要点；手机屏内文案 ≤18 字/条。
- **电脑卡**：标题一句 + 一句正文；窗口内只放示意数据。
- **卡片墙**：每格标题 ≤8 字、说明 ≤16 字；一块强调色。
- **流程图**：节点 ≤10 字、说明 ≤18 字；判断只留一个。
- **宣传图**：大标题 2 行 + 3 条卖点 + 一个价格/CTA。

原则：卡片文字是「海报级」——短、硬、能独立成立；不写完整长句。

## 6. CTA（文末/结尾卡）

- 关注类：「关注 XX，每天一个能上手的开源项目。」
- 收藏类：「这套图建议收藏，选型时对照着看。」
- 互动类：「你踩过哪个坑？评论区聊聊。」
- 引流类：「项目地址见阅读原文 / 回复『架构』领取。」
一次只给一个主 CTA，别堆五个。

## 7. 四类体裁大纲

### 7.1 产品发布
1. 导语：痛点 → 我们做了什么 → 一句话价值。
2. 一、它解决什么问题（场景化）。
3. 二、核心能力（3–4 点，每点一张卡/一节）。
4. 三、怎么用（3 步上手 + 截图）。
5. 四、边界与价格/开源协议。
6. CTA：下载/试用/Star。

### 7.2 项目推荐
1. 导语：为什么现在推荐它（一句钩子 + 数据）。
2. 一、它是什么（定位一句话 + 技术栈）。
3. 二、结构/架构图（配架构图）。
4. 三、值得推荐的 3 个理由。
5. 四、真实边界（成熟度、适用场景、坑）。
6. 项目地址 + CTA。

### 7.3 教程一图流
1. 导语：承诺「照着点就行」+ 最终效果。
2. 一、先看全貌（一张流程图）。
3. 二～N、分步骤（每步一图 + 一句要点 + 避坑）。
4. 总清单（可勾选）。
5. 边界/截止/风险。
6. CTA：收藏 + 领取模板。

### 7.4 数据复盘
1. 导语：一个反常识结论或一个扎眼数字。
2. 一、指标体系（一张指标图）。
3. 二～N、逐个指标：定义 + 怎么看 + 阈值/公式。
4. 常见误判 / 组合判断。
5. 行动清单。
6. CTA：领取看板/模板。

### 7.5 产品宣发（G）
1. 导语：先给画面/结果，再给一句价值。
2. 一、它解决什么问题（一个具体场景）。
3. 二、产品全景（宣传主视觉 + 3 个能力）。
4. 三、三个使用场景（手机 / 桌面 / 团队协作）。
5. 四、价格/协议/上手路径（表格 ≤4 列）。
6. 五、边界与不适合的人。
7. CTA：试用 / Star / 预约。

### 7.6 设备图文（H）
1. 导语：还原「你正在用手机/电脑处理这件事」。
2. 一、先看结果（一张设备截图）。
3. 二～N、操作步骤（3–5 步，每步一图 + 一句要点）。
4. 它为什么这样设计（流程图或对比）。
5. 避坑与限制。
6. 适合谁 / 不适合谁。
7. CTA：收藏 / 领取模板。

## 8. 两版差异（同题两版怎么拉开）

| 维度 | V1 深色科技版 | V2 浅色清新版 |
|---|---|---|
| 读者 | 开发者 / 技术决策者 | 产品、运营、泛技术爱好者 |
| 语气 | 硬核、克制、讲边界 | 轻快、友好、讲场景 |
| 标题 | 更技术、更具体 | 更利益点、更好懂 |
| 图 | 深色卡、代码窗、架构图 | 浅色卡、产品截图、图解 |
| 正文 | 参数/技术细节多 | 案例/体验多 |

**注意**：只换配色/语气 = 换皮。至少一版的卡片顺序、主视觉类型或文体要与另一版不同（见 [directions](directions.md) 与 [image-design-system](image-design-system.md) 的反模板装饰规则）。

## 9. 参考文案范式（实战提炼）

### 9.1 标题（来自 15 篇参考）
- **开源投递体**：`开源｜一款 <品类>，支持 <能力1>、<能力2>`
- **挖宝体**：`又挖到一个<品类>神器：<名字>。<数字> Star，<协议>`
- **数字钩子**：`1.4 万 Star 的<品类>：<名字>`
- **反常识**：`官方越说不做，它越火：<事实>`
- **对比存量**：`4 个插件装完，我只留下 2 个`
- **教程承诺**：`照着点就行：<结果>，N 步搞定`
- **产品宣发**：`X 2.0 来了：<一句卖点>` / `一张图，把<对象>讲清楚`
- **设备场景**：`在手机里，把<事情>办了` / `桌面上的一张<东西>`
贴图标题 ≤20 字，一行钩子；文章标题 ≤30 字，钩子在前 20 字。

### 9.2 小绿书配文（图片消息描述，≤100 字）
```
第一句：一句结论或痛点提问（钩子）。
第二段：它是什么 + 解决什么（1–2 句）。
分点：①②③ 或 • 列 2–4 个能力/要点（每点一句）。
一句提醒/边界（可选）。
地址 / 关键词 / CTA（可选）。
#话题1 #话题2
```
允许用 `①②③`、`📌`、`🔥` 做分区，但不要满屏 emoji；配文是「图的海报解说」，不重复图内大字。

### 9.3 开头（导语）四选一
痛点场景 / 结论先行 / 具体数字 / 亲历口吻——参考文章几乎都是「痛点场景」，用「做开发的朋友应该都体验过这样的窘境」这类共鸣句起手。

### 9.4 结尾 CTA（一个就够）
- 关注：`关注「XX」，每天一个能上手的开源项目。`
- 收藏：`这套图建议收藏，选型时对照着看。`
- 互动：`你踩过哪个坑？评论区聊聊。`
- 领取：`回复「关键词」领取模板 / 看阅读原文。`
