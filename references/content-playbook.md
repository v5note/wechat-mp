# 文案手册（content-playbook）

标题、摘要、导语、小标题、卡片文案、CTA 的写法与四类体裁大纲。目标是「有钩子但不标题党、信息密度高但读得动」。

## 1. 标题公式（文章 3–5 条，贴图 2–3 条）

微信标题在信息流只露出前 ~20 字，**把钩子放最前**，用具体名词与数字，少用形容词。

- **数字 + 结果**：27 张支付架构图，我本来舍不得发
- **反常识 / 转折**：放弃了若依，我选择了它
- **痛点 + 解法**：C 盘又满了？这次我只说了几句话
- **身份 + 场景**：做 Java 后台，先别急着上微服务
- **教程承诺**：照着点就行：10 亿 Token 四步领到手
- **对比选型**：Rust 版若依值得用吗？先说真实边界

贴图标题 = 一张封面的主标题，≤20 字，两行内，一句结论。

**自检**：能否一句话说清「给谁、解决什么、得到什么」？不能就重写。标题不夸大、不用「震惊/必看/史上最」。

## 2. 摘要（≤54 字）

公式：**对象 + 价值 + 一个具体锚点**。独立成立，不重复标题原句，不写「本文将介绍…」。

例：把 27 张支付架构图整理成一册：收银台、交易、清结算、对账全链路，附下载。

## 3. 导语公式（3–5 句）

开头直接上冲突，别铺垫。四种开场任选：
1. **痛点场景**：先还原读者此刻的窘境。
2. **结论先行**：一句话给答案，再解释。
3. **具体数字**：用真实数字/结果抓住注意。
4. **亲历口吻**：「我用了两周，发现…」。

导语结尾留一句「本文解决 X」，把读者带进正文。

## 4. 小标题（节标题）

- 结论式优于名词式：二、真正拖慢你的不是数据量，是索引 好过 二、性能优化。
- 每节只解决一个问题；节与节之间有递进或并列关系。
- 编号全文统一（一、二、三 或 01 02 03）。

## 5. 卡片文案（贴图）

- **封面**：主标题两行、副标题一行、3–4 个标签。主标题要有落差或结果感。
- **要点卡**：标题 ≤14 字结论句 + 正文 ≤60 字。
- **图解卡**：标题一句「怎么运作」；图注一句小结。
- **对比卡**：维度名短，左右各一句短语 + ✓/✗。
- **结尾卡**：3–5 条回顾 + 一句 CTA。

原则：卡片文字是「海报级」——短、硬、能独立成立；不写完整长句。

## 6. CTA（文末/结尾卡）

- 关注类：「关注 XX，每天一个能上手的开源项目。」
- 收藏类：「这套图建议收藏，选型时对照着看。」
- 互动类：「你踩过哪个坑？评论区聊聊。」
- 引流类：「项目地址见阅读原文 / 回复『架构』领取。」
一次只给一个主 CTA，别堆五个。

## 7. 四类体裁大纲

### 7.1 产品发布
1. 导语：痛点 → 我们做了什么 → 一句话价值。
2. 一、它解决什么问题（场景化）。
3. 二、核心能力（3–4 点，每点一张卡/一节）。
4. 三、怎么用（3 步上手 + 截图）。
5. 四、边界与价格/开源协议。
6. CTA：下载/试用/Star。

### 7.2 项目推荐
1. 导语：为什么现在推荐它（一句钩子 + 数据）。
2. 一、它是什么（定位一句话 + 技术栈）。
3. 二、结构/架构图（配架构图）。
4. 三、值得推荐的 3 个理由。
5. 四、真实边界（成熟度、适用场景、坑）。
6. 项目地址 + CTA。

### 7.3 教程一图流
1. 导语：承诺「照着点就行」+ 最终效果。
2. 一、先看全貌（一张流程图）。
3. 二～N、分步骤（每步一图 + 一句要点 + 避坑）。
4. 总清单（可勾选）。
5. 边界/截止/风险。
6. CTA：收藏 + 领取模板。

### 7.4 数据复盘
1. 导语：一个反常识结论或一个扎眼数字。
2. 一、指标体系（一张指标图）。
3. 二～N、逐个指标：定义 + 怎么看 + 阈值/公式。
4. 常见误判 / 组合判断。
5. 行动清单。
6. CTA：领取看板/模板。

## 8. 两版差异（同题两版怎么拉开）

| 维度 | V1 深色科技版 | V2 浅色清新版 |
|---|---|---|
| 读者 | 开发者 / 技术决策者 | 产品、运营、泛技术爱好者 |
| 语气 | 硬核、克制、讲边界 | 轻快、友好、讲场景 |
| 标题 | 更技术、更具体 | 更利益点、更好懂 |
| 图 | 深色卡、代码窗、架构图 | 浅色卡、产品截图、图解 |
| 正文 | 参数/技术细节多 | 案例/体验多 |
