# 图片样式规范（image-design-system）

贴图卡片、文章封面、正文配图的统一视觉语言。所有数值都是**硬规格**：模板和脚本按这里实现，改版只改 [../assets/tokens.css](../assets/tokens.css)，不改单张图。

## 0. 三条总原则

1. **一图一意**。一张卡只讲一个点；标题最多两行；读者扫一眼就懂。
2. **强调唯一**。每张卡只用一个强调色强调一个关键词或一个数字，多了就散。
3. **规矩的栅格感**。所有元素对齐 12 栅格与统一安全区；留白是设计的一部分，不是浪费。

## 1. 画布 / 栅格 / 安全区

| 用途 | 尺寸 | 比例 | 说明 |
|---|---|---|---|
| 贴图卡片（单图消息一张） | **1080 × 1440** | 3:4 | 竖版主战场，微信图片消息按此比例满屏 |
| 文章封面（首图） | **1080 × 460** | 2.35:1 | 信息流/分享卡封面；另出 1080×1080 方版备选 |
| 文章正文配图 | **宽 1080**，高 560–1440 | 自适应 | 架构图/流程图为高图，截图为 16:9 |
| 文章内分隔横幅 | 1080 × 320 | — | 章节过渡/引用大字 |

- 栅格：12 列，列宽 74px，槽宽 24px，左右安全边距 **72px**。
- 安全区：四周 **≥ 64px**（推荐 72px）；主标题、正文、标签都不得越界。
- 圆角：卡片内面板 24px，标签 pill 999px，图表节点 16px。
- 贴图套图总张数：封面 1 + 要点 3–7 + 结尾 1 = **5–9 张**；超过 9 张拆成两组。

## 2. 色彩系统（两套主题，见 tokens.css）

两版 = **一浅一深两套主题**（默认深色科技 + 浅色清新，也可换成风格库里任意一深一浅）。
同一主题内强调色只用一种（品牌色）；第二色仅用于警示/对比，且只在对比卡出现。

### 2.0 明暗判定（硬规则）

| 明暗 | 判定（`scripts/palette.mjs`） | 归属主题 |
|---|---|---|
| **深色系 dark** | `--bg1` 相对亮度 < 0.5 且 `--text` 亮度 > 0.5 | dark / night-cyan / guofeng / forest / ocean / cyber / midnight / desk / promo |
| **浅色系 light** | `--bg1` 相对亮度 ≥ 0.5 且 `--text` 亮度 < 0.4 | light / magazine / mono / aurora / cream / sky / rose / baize / ios / bento / blueprint |

- **两版一浅一深**：默认交付必须一个深色系、一个浅色系；两版同明暗 = 不合格（读者分不出 A/B）。
- **不许同色系近亲**：两版强调色相差 < 40° 且同明暗时判 fail（例如 aurora 与 sky）。
- 同一版内不许混用两种明暗：一张深底卡 + 一张浅底卡会让读者以为换了一期内容。

### 用色规则
- 大标题用 --text；关键词高亮用 --accent；说明文字用 --text-2/--text-3。
- 大面积不用纯 #000 / 纯 #FFF，用上面的近黑/近白，避免刺眼。
- 正文与背景对比度 ≥ 4.5:1（WCAG AA）。
- 渐变只用于背景与强调色块，**不用于正文文字**。

## 3. 字号阶（1080 画布，PingFang SC / 思源黑体）

| 角色 | 字号 | 字重 | 行高 | 字距 |
|---|---|---|---|---|
| 眉标 kicker（品牌 + 栏目） | 26 | 600 | 1.2 | 2px |
| 主标题 headline | 84–104（两行时取 88） | 800 | 1.06 | -2px |
| 副标题 subtitle | 32 | 500 | 1.5 | 0 |
| 正文 body | 28 | 400 | 1.7 | .5px |
| 图注 / 说明 caption | 24 | 400 | 1.5 | .5px |
| 标签 chip | 24–26 | 600 | 1 | .5px |
| 页脚 footer | 20–22 | 400 | 1.4 | 1px |
| 序号（可选，仅内容真是序列时） | 120–160 | 800 | 1 | -4px（透明度 .10） |

规则：标题行数 × 字号不超出可用宽（1080−144×2=936px）；两行标题优先在语义处断行，不让一个词孤零零掉到第二行。

## 4. 十种卡片原型（5 基础 + 5 画面）

每张卡都遵循同一骨架：**品牌头 → 主区（标题 + 主视觉）→ 页脚（标签/页码）**。变化在「主区」。
前 5 种是通用版式，后 5 种是画面风格专用版式（手机 / 电脑 / 卡片墙 / 流程图 / 产品宣传）。

### 4.1 封面卡 Cover（首图 = 钩子）

首图是**六宫格里唯一被看到的一张**，只承担一件事：让读者觉得「点进去有货」。版式自上而下、整体上移，下方的留白当呼吸，不要把内容全压到页脚。

| 层 | 内容 | 规格 |
|---|---|---|
| 1 主标题 | 两行，「结果 / 反常」放第一行，关键词用强调色 | 96–116px/800/1.02–1.08；按最长一行 7 / 10 / 13 字自动降档（第 3 节字号阶 `.headline.hook` / `.hook2` / `.hook3`），两行都不超 936px |
| 2 副标题 | 一行，讲清「什么东西 / 给谁」 | 32px/500 |
| 3 眉标 | 栏目 pill，放在标题之下做署名，**不压在主标题上方** | 26px |
| 4 首屏预览 | `thumbs`：后面 4 张卡的关键词缩略 + 结尾卡，前缀「往下还有」 | 每格 3:4；缩略图**只放关键词，不放句子**（小尺寸下句子必糊） |
| 4' 主视觉（替代） | 有真实截图 / 关键图解时，用 `hero` 替掉 `thumbs` | 截图或图解 ≤ 卡片宽 60% |
| 5 卖点条 | 2–3 个最有说服力的标签 | 24px pill；⭐ 只给真数据，不要装饰 |

规则：
- 一屏只保留**一个**视觉重心（预览缩略图 或 主视觉），不要两者叠满。
- 首图不要塞清单、表格、流程图等「读完才知道是什么」的内容；这些放第 2 张往后。
- 封面标题字号比内页大 1–2 档：同一期里首图必须一眼比其它卡标题粗大。
- 右上 badge 仅在 brief 明确需要时加，不要用「NEW」这种装饰。
- 检查方法：把整期缩略成 320px 宽丢进六宫格，首图标题仍能读出**一句话结论**，才算合格。

    品牌 栏目
    两行主标题（结果 / 反常在前，关键词高亮）
    一行副标题
    ┌─────────────────────┐
    │  往下还有  缩略 缩略 缩略 缩略 结尾 │

## 首图版面（cover.layout · 8 种，来自 [style-cases](style-cases/README.md)）

参考 35 篇公众号贴图首图归纳出的版面骨架，选哪个由**赛道**决定，不由配色决定：

| layout | 代表账号 | 适用主题 | 关键字段 |
|---|---|---|---|
| `tool-brief` / `annotated-illu` | show-me / Skills Manager / 阿蓝蓝 | 开源工具、Skill、组件、网站推荐 | accentBg / note / hero / tiles[{name,badge}] |
| `dev-dark` | Supabase / Aegis / magpie | 后端、平台、基建 | hero / points[{t,d}] / strip（底部边界提醒） |
| `color-grid` | Prompt 常用框架 | 清单、框架、模板 | formula / cells[{t,d}] / strip |
| `bento-stack` | TANSOR LAB | 有产品界面、要露场景 | hero（界面铺底）+ declare（宣言条） |
| `layout-sample` | 350 种排版 / B 端工作台 | 作品集、图鉴、合集 | samples[{src,t}] / strip |
| `diagram-poster` | AI Agent 架构 | 原理图解、架构总览 | hero（图解）+ summary |
| `pin-red` | Pin UI | 组件库、设计资源、品牌新品 | tiles[{t,d}] / points[] |

两种「真截图替身」：没有产品界面可截时，用 `desktop` 组件渲染多端窗口（首图用 `size:sm, viewH:250, ui:list`，窗口内**只放关键词与数字，不放句子**），并在 spec 里写清这是示意。

共同约束：标题仍用 `hook` 字号阶；一屏只留一个视觉重心；页脚由模板固定在底部（`.card .page>.ft` 绝对定位），主区再高也不会把页脚顶走。

### 4.2 要点卡 Point
- 左上：小标签 + 小栏目名；只有内容是序列时才用 01 / 02 序号。
- 标题：一句结论式短句（≤14 字）。
- 正文：2–3 行说明（≤60 字）。
- 主视觉：一张截图或小图解，或纯文字留白（图少字多时）。
- 每卡只讲一个卖点。

### 4.3 图解卡 Diagram
- 标题：一句「怎么运作 / 由什么组成」。
- 主视觉：流程图 / 层级图 / 架构图 / 漏斗（见第 5 节组件）。
- 底部图注：一句小结 + 图例。
- 这是「获客主力图」，信息密度可以高，但要有明确的阅读方向（自上而下或自左而右）。

### 4.4 对比卡 Compare
- 左右两栏或上下两行：旧 vs 新 / A vs B。
- 表头用色区分（左灰右强调），逐行给 ✓ / ✗ + 短语。
- 一行一个维度，最多 4–5 行。

### 4.5 结尾卡 Ending
- 标题：号召句（现在就试 / 收藏备用 / 关注不迷路）。
- 3–5 条要点回顾（每条一行，前置 ✓ 或序号）。
- **下期预告**（可选但推荐）：`nexts` 2–3 条「标题 + 一句话说明」，和首图的「往下还有」首尾呼应，让读者知道这是个持续更新的栏目，而不是一次性内容。
- CTA 区：项目地址 / 回复关键词 / 关注 / 在看 / 分享，配一个**真实可扫**的二维码（见 2.7）。
- 品牌落款。

### 4.6 手机卡 Phone

- 版式：左文右机（文字 1/2、手机 1/2），或 `layout:"stack"` 上文下机。
- 真机框：404×820，外框圆角 60，屏幕圆角 49，刘海 118×32，状态栏 58，Home Indicator。
- 屏幕三种：`chat`（对话 + 输入框）、`feed`（信息流/发现页）、`app`（工作台 + 图表 + 列表）。
- 文字区：kicker / 标题（2 行、≤8 字/行）/ 副标题 / 3 条要点 / 2–3 个标签。
- 手机完整落在安全区内；示意 UI 必须在图注或卡面标「示意」。

### 4.7 电脑卡 Desktop

- 版式：kicker + 标题 + 一句正文 → 桌面窗口占下半屏 → 图注。
- 结构：菜单栏 34 + 窗口标题栏 50 + 窗口主体（侧栏 190 + 内容区），窗口宽 936。
- 内容三种：`dashboard`（3 指标 + 柱图 + 2 小卡）、`board`（三列看板）、`editor`（代码/编辑器）。
- 窗口内数字只放演示值；真实后台请用 `shot` 截图，不画假界面。

### 4.8 卡片墙 Bento

- 网格：3 列（`cols:3`）或 4 列；间距 14；行高随容器均分。
- 格子字段：`t` 标题、`d` 一句说明、`icon`、`num` 大数字、`tags[]`、`span:2` 横跨、`tall:true` 纵跨、`tone:"accent"|"ink"`。
- 一块强调色 + 一块墨色足够；其余白/浅底。格子大小要表达信息层级，不做等分九宫格。
- 标题 ≤8 字，说明 ≤16 字；大数字只放一个。

### 4.9 流程图卡 Flowchart

- 画布宽 936；起始/结束胶囊 380×76；步骤节点 560×88；判断菱形 360×168；分支节点 356×124。
- 纵向间距：节点间 44–52，判断后 42，分支后 44；整图高度随内容计算。
- 连线：SVG 正交折线 2.4px，箭头 7px，颜色取 `--accent`；分支标注「是 / 否」加底 pill。
- 步骤 2–4 个、判断 1 个、分支各 1 个；节点标题 ≤10 字、说明 ≤18 字。

### 4.10 产品宣传卡 Promo

- 结构：`promoBadge` → 2 行大标题 → 副标题 → 产品舞台（手机/电脑/真截图 + 聚光圈 + 3 个浮签 + 价格）→ 底部 3 条卖点 + 单一 CTA。
- 舞台最小高 560；聚光圈 720；手机 360×730（舞台内旋转 -7°）；电脑 760 宽。
- 一屏只推一个产品、一个价格、一个 CTA；卖点条 ≤3 条；价格/协议必须真实。

## 5. 视觉组件（可直接复用）

- **浏览器框 browser frame**：圆角 24，顶部 44px 工具条 + 三个圆点或一个 URL pill，内部放截图/UI 模拟；带 1px 描边与柔和阴影。
- **代码/终端窗 code window**：深色底，顶部红黄绿三点 + 文件名 tab，等宽字体，行号淡显。
- **流程图 flow**：圆角矩形节点（accent 描边/浅底），细箭头连接，箭头可带 16px 标签；节点分 3–5 步，横向或纵向排列。
- **层级/架构图 stack**：自上而下的分层带（接入层→服务层→数据层），每层一种低饱和底色，层内小方块代表模块。
- **对比 compare**：两列卡片，行高一致，✓ 绿 / ✗ 灰红。
- **图标簇 icon cluster**：3–5 个线性图标围绕一个中心，做「能力集合」的视觉。
- **标签 chip / 徽章 badge**：pill，描边 + 半透明底；badge 用实心 --badge。
- **序号（可选）**：巨大数字，透明度 .10；只在内容真是序列时用，不要拿 01/02 当装饰。
- **手机真机框 phone**：404×820，刘海 + 状态栏 + Home Indicator；屏内可放对话、信息流、工作台三套 UI；放在 3:4 卡里默认左文右机。
- **桌面窗口 desktop**：macOS 菜单栏 + 窗口 + 侧栏 + 内容区 + 可选 Dock；窗口宽 936，适合「上文下窗」。
- **大小格墙 bento**：3–4 列网格，格子可横跨/纵跨；一块强调色 + 一块墨色，其余白/浅底。
- **流程图 flowchart**：胶囊起止 + 步骤节点 + 菱形判断 + 左右分支 + 汇合；SVG 正交连线，必须能一眼读出方向。
- **产品舞台 promo**：聚光圈 + 手机/电脑/真截图 + 3 个卖点浮签 + 价格 pill；海报级标题 + 底部卖点条 + 单一 CTA。
- **背景纹理**：浅色版点阵/网格纸；深色版径向冷光 + 极淡网格；宣传图用底部聚光。

## 6. 图标规范

- 统一 **线性图标**：2px 描边、24×24 网格、圆角端点、单一 currentColor。
- 成套取自 [../assets/icons.svg](../assets/icons.svg)（star / check / arrow / cube / layers / code / terminal / search / share / bolt / shield / chart / qr / new-badge / link / clock 等）。
- 在 HTML 中用：**<svg class="ic"><use href="#ic-star"/></svg>**，颜色随父级 color（即 --accent 或 --text-2）。
- 一个画面里图标风格必须一致；尺寸只用 20 / 24 / 32 / 40 四档。
- 不混用实心图标与线性图标；不旋转图标做装饰。

## 7. 正反例

| ✓ 这样做 | ✗ 别这样 |
|---|---|
| 一张卡一个信息，标题两行讲透 | 一张卡塞三个卖点、五行小字 |
| 关键词只高亮一次 | 半张卡都在变色 |
| 主视觉占下半屏、对齐栅格 | 截图歪斜、贴边、被裁一半 |
| 深色主题统一冷光 + 一种强调色 | 深色底上放大红大绿 |
| 图标线性成套、同尺寸 | 东拼西凑、大小不一 |
| 留白 72px 安全区 | 文字顶到边缘 |

## 8. 贴图套图节奏（Series）

一套贴图就是一次「滑动阅读」。推荐节奏：

1. **封面卡**：抛结论 + 主视觉，让人想左滑。
2. **要点卡 ×2–3**：每个卖点一张，序号递增。
3. **图解卡 ×1–2**：流程图/架构图，是收藏与转发的关键。
4. **对比卡 ×0–1**：新旧/竞品对比（有就上）。
5. **结尾卡**：回顾 + CTA + 二维码。

每张卡右下角可放 3/9、4/9 页码，弱化处理（--text-3）。

## 9. 参考风格版式（来自 35 张贴图实战）

真实爆款贴图比「干净模板」更密的三个原因，可迁移到本项目：

1. **顶部信息条 + 大标题 + 一个视觉锚点**：大标题常 3–4 行、字号占屏 20–28%，关键词用强调色或色块；标题上方加一个小 pill（栏目/协议/期号）。
2. **主视觉必须"像一个真实东西"**：真产品截图、架构图、卡片墙、清单格——不要大面积空白。截图配一枚「示意图/官方界面」小胶囊做诚实标注。
3. **分区有结构**：能力用 2×2 卡片、合集用 2–3 列字段卡（形态/语言/许可/星数）、清单用勾选行、数据用大字。底部常有一条「先了解/边界」提示条。

可借用的小元素：手绘箭头/下划波浪（浅色系）、角标页码（01/06）、四色分区（sky）、细网格（cyber）、纸纹（cream）。
但**不要**回到「全大写小标签 + 中点 A·B·C + 每卡 01/02/03 当装饰」的 AI 模板腔。

## 11. 新增视觉组件规格

| 组件 | hero.type | 用法 | 关键约束 |
|---|---|---|---|
| 编号步骤 | `steps` | nodes[{num,t,d}] | 3–5 步；号码方块用强调色 |
| 字段卡片墙 | `matrix` | items[{num,t,desc,fields[{k,v}],tags}] + cols | 4–9 项；字段 ≤4 行 |
| 勾选清单 | `checklist` | items[字符串或 {t,b,d}] | 3–6 条；勾选框统一 |
| 键值表 | `kv` | rows[{k,v}] | 行高一致；偶数行浅底 |
| 数据大字 | `stats` | items[{num,label}] | 2–4 个；数字用强调色 |
| 要点列表 | `blist` | items[{t,d,icon|num}] | 3–5 条 |
| 手机屏 | `phone` | screen(chat/feed/app) / name / messages / items / stats | 真机 404×820；屏内文字 ≥13；示意要标注 |
| 桌面窗 | `desktop` | app / ui(dashboard/board/editor) / nav / tabs / stats | 窗口 936 宽；内容不超 2 层 |
| 大小格墙 | `bento` | items[{t,d,icon,num,tags,span,tall,tone}] + cols | 3–4 列；一块 accent + 一块 ink |
| 流程图 | `flowchart` | start / steps[{t,d}] / decision{q,yes,no} / end | 2–4 步 + 1 判断；高 ≥900 的配图 |
| 产品舞台 | `promo` | device(phone/desktop) / src / tags / price / priceNote | 一屏一产品一价格；卖点 ≤3 |

对应卡片变体 `cover` / `point` / `diagram` / `compare` / `list` / `grid` / `stat` / `quote` / `ending` / `phone` / `desktop` / `bento` / `flowchart` / `promo` 已在 `scripts/visuals.mjs` 注册，字段见 [style-catalog](style-catalog.md) 第 1 节。
