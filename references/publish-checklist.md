# 发布清单（publish-checklist）

每个样例上线前逐项打勾。贴图与文章分别一套，最后是「交付前自检」。

## A. 贴图（图片消息 / 小绿书）

- [ ] 图片数量 5–9 张，顺序：封面 → 要点 → 图解/对比 → 结尾。
- [ ] 每张 1080×1440（3:4），PNG，单张 ≤ 2MB（超了就压到 JPG 90）。
- [ ] 首图（封面）3 秒能看懂主题：大标题（首行是结果/反常）+ 一个视觉锚点（真实截图，或 `thumbs` 首屏预览「往下还有」）。
- [ ] 首图缩到六宫格（约 320px 宽）仍能读出一句结论；标题没被压到内页字号。
- [ ] 每张安全区 ≥64px，无文字贴边、无溢出、无被裁。
- [ ] 每卡一个信息、一个强调色；标题 ≤2 行。
- [ ] 文字清晰：最小字号 ≥20px（成图后）。
- [ ] 标题 ≤20 字，钩子在前。
- [ ] 配文（图片消息描述）≤100 字，含 1 个 CTA 或关键词。
- [ ] 末尾卡有回顾 + CTA + 二维码/关键词。
- [ ] 话题标签 1–3 个；位置/可见范围按需设置。
- [ ] 手机预览走一遍：滑动节奏顺、无错字。

## B. 文章（图文消息长文）

- [ ] 标题取推荐条，钩子在前，不标题党。
- [ ] 摘要 ≤54 字，独立成立。
- [ ] 正文 ≥800 字，配图 ≥3 张（总览/介绍图 + 图解或截图）。
- [ ] 封面 1080×460（2.35:1），另备 1:1 方图；封面清晰不含糊。
- [ ] 正文段落每段 ≤4 行；行高/字号/颜色按 article-format。
- [ ] 小标题编号全文统一，命名结论式。
- [ ] 每个图位有「图N：一句话」图注，图片与上下文相关。
- [ ] 正文图片宽度 100%、圆角、居中、图间有文字过渡。
- [ ] 表格列数 ≤4，移动端不横向溢出；超了改列表。
- [ ] 强调样式克制：加粗/高亮/引用/分割只用少数几种。
- [ ] 技术类写了「边界 / 风险 / 适用性」。
- [ ] 文末有项目地址/参考 + 一个主 CTA。
- [ ] **HTML 是可粘贴片段**：只有根 `<section>`，无 doctype/html/head/body/title；只用 p/span/strong/img，无 h1/h2/figure/figcaption/hr/table/blockquote/div。
- [ ] 无 `<style>`/`<script>`/外链；无 `font-family`、`letter-spacing`、`max-width`、`margin:0 auto` 这类微信会清理的属性。
- [ ] **粘贴方式**：浏览器打开 article-import.html → 点「复制全文」→ 粘进编辑器；**不要用记事本/纯文本编辑器打开 article.html 复制**（剪贴板只有纯文本，粘过去就是标签源码）。
- [ ] 粘贴后确认编辑器里是**渲染结果**而不是 `<section style=…>` 源码。
- [ ] **正文配图手动上传**：按图注顺序上传 `article/images/fig1..N`，替换相对路径占位。
- [ ] 粘完逐项核对：小标题蓝色加粗、图注在图下方、分割线留白、列表逐条分行、无多余空行。
- [ ] 原创声明 / 转载说明 / 话题 / 定时发布 按需设置。
- [ ] 手机预览：无乱码、无图片加载失败、无死链。
- [ ] 真实产品/后台截图：已确认来源与可用范围；测试数据可直接使用，生产数据按需脱敏。

## B2. 视频号（可选产出）

- [ ] 封面 1080×1920（9:16），主体避开顶部 220px / 底部 360px。
- [ ] 分镜 ≥4 镜，前 3 秒有钩子。
- [ ] 单屏字幕 ≤12 字，与口播同步。
- [ ] 一条视频只讲一个点；结尾一个 CTA；与文章/贴图同源同事实。
- [ ] 口播稿有话题标签；首帧与封面一致。
- [ ] **视频文件**：默认三件套不含 mp4——要直接发就要 `--render-video` 出 `video/video.mp4`；交付时明确告诉用户「是脚本还是成片」，别让人以为漏了。
- [ ] （有 mp4 时）1080×1920 / 30fps / H.264+AAC；中文字幕正常显示；有旁白的版本音量正常，TTS 机器音已在交付说明里注明。

## C. 交付前自检（skill 收尾必过）

- [ ] 四个样例齐全：V1 贴图、V1 文章、V2 贴图、V2 文章。
- [ ] 已按 [style-catalog](style-catalog.md) 选定风格（主题 + 骨架），不是随手套默认。
- [ ] （如出视频）`video/cover.png`、`口播稿.md`、`分镜.md` 齐全且检查通过。
- [ ] 每个样例都带：标题备选、摘要、正文（Markdown 或逐图文案）、配图/发布清单。
- [ ] **两版一浅一深**：一版深色系主题、一版浅色系主题；两版同明暗或同色系近亲（如 aurora + sky）直接判不合格。
- [ ] 单版内部明暗统一：一批贴图不混深底与浅底。
- [ ] 两版差异清晰（卡片顺序/主视觉/骨架/语气不同），不是简单换色。
- [ ] 所有 PNG 尺寸正确、逐张目检过。
- [ ] 文章 Markdown 与 HTML 内容一致；`article/粘贴说明.md` 已生成并随产物交付。
- [ ] 图注编号连续、无跳号。
- [ ] 无虚构事实未标注；演示数据的样例已声明「仅为演示」。
- [ ] 文件按约定目录归档，命名清晰可交付。
- [ ] 涉及真实产品/数据/事件时，`facts.md` 已生成且每条有来源。
- [ ] 出现真实品牌/产品时，`brand-spec.md` 已生成，logo/截图已核验。
- [ ] （可选增强）如做过方向提案，`方向确认.md` 记录了用户选择的原话。
- [ ] （可选）`polish-log.md` 记录了至少 1 轮打磨（最伤三处 + 改了什么）。
- [ ] `node scripts/check.mjs` 为 0 fail（警告已逐条确认）。
- [ ] `node scripts/validate-pair.mjs --all` 为 0 fail（一浅一深 + 结构不同两条都过）。
- [ ] 已运行 `node scripts/preview.mjs --demo examples/demo` 刷新 overview 图。
