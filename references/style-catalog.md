# 风格库（style-catalog）

> 从 **35 张贴图 + 15 篇文章 + 3 个视频号**，以及本次补充的 **手机 / 电脑 / 卡片 / 流程图 / 产品宣传图 / 图文长文** 参考素材中提炼出的可复用风格 DNA。
> 选风格不是选颜色，而是选**画面骨架 + 版面结构 + 图文关系 + 语气**。本文件是「智能选题 → 选风格」的查表依据，
> 所有主题令牌落在 [../assets/tokens.css](../assets/tokens.css)，样张在 [../assets/style-specimens/](../assets/style-specimens/)。

当前规模：**20 套主题 · 16 种贴图风格 · 6 类画面风格 · 8 种文章骨架 · 3 种视频形式**。

## 0. 四步选风格

1. **判素材档**（[materials](materials.md)）：抽象概念/方法论 → T0 程序化；真实产品/公司 → T1 必须有真截图/logo；需要氛围 → T2 生成图。
2. **判体裁**（[content-playbook](content-playbook.md)）：产品发布 / 项目推荐 / 教程一图流 / 数据复盘 / 横评对比 / 口播视频。
3. **选画面风格**：手机 / 电脑 / 卡片 / 流程图 / 产品宣传图 / 纯贴图——先定「读者看到的是什么场景」，见第 1 节。
4. **选主题 + 骨架**：同一画面风格可换任意主题配色；再定卡片序列与文章骨架。

**默认交付**：2 个版本（深色科技 + 浅色清新）× 2 种格式（贴图 + 长文）= 4 个样例。
**进阶交付**：从风格库显式挑 1 套「画面风格 + 主题 + 骨架」，做 1 个高完成度样例；需要时再加 1 个视频号产出。

## 1. 画面风格（6 类 · 先定「长什么样」）

画面风格是**版式家族**，主题是**配色令牌**，两者解耦：`ios` 主题配 `phone` 卡是默认组合，也可以把 `phone` 卡放进 `dark`、`rose`、`baize` 等任意主题。

| 画面风格 | 默认主题 | 卡片变体 | 核心 hero | 读者感受 | 最适合 |
|---|---|---|---|---|---|
| **手机风格** | `ios` | `phone` | `phone`（chat / feed / app） | 「像在看自己的手机」 | App、小程序、对话式产品、移动端教程 |
| **电脑风格** | `desk` | `desktop` | `desktop`（dashboard / board / editor） | 「像在看一个真实工作台」 | 桌面软件、后台、浏览器工具、IDE |
| **卡片风格** | `bento` | `bento` | `bento`（span / tone） | 「信息有主次，扫一眼就懂」 | 能力清单、合集、卖点墙、对比前置 |
| **流程图风格** | `blueprint` | `flowchart` | `flowchart`（判断 + 分支） | 「一条线讲清怎么走」 | 流程、审批、教程、决策、SOP |
| **产品宣传图** | `promo` | `promo` | `promo`（产品舞台 + 价格 + 卖点） | 「这是一张能直接发的海报」 | 新品、发布、预售、促销、卖点主视觉 |
| **文章图文** | 任意 | — | 文章骨架 + 配图 | 「像一篇能读完的长文」 | 项目推荐、复盘、教程、产品宣发 |

> **搭配原则**：一期内容只用 1 个主画面风格 + 1 个辅助版式（如手机风格 + 卡片风格收尾）。
> 同一套图里不要手机、电脑、宣传图三种主视觉平权，读者会失焦。

## 2. 画面风格详解（怎么用、怎么不翻车）

### 2.1 手机风格 · `phone`

- **画面**：真机外框 404×820（3:4 卡内可满高），含刘海、状态栏、Home Indicator；屏幕内容三种：
  `chat`（对话，含气泡/输入框）、`feed`（信息流/发现页）、`app`（工作台/图表/列表）。
- **版式**：`phone` 卡默认**左文右机**（文字 1/2、手机 1/2）；标题 ≤2 行、≤8 字/行；手机必须完整落在安全区内。
- **适合**：App、小程序、对话式助手、移动端操作教程；也适合把「一句话就能完成」讲成场景。
- **诚实**：手机 UI 是**示意界面**，卡面/图注要标「示意」；有真实截图时优先 `shot`，不要用假 UI 冒充真产品。

### 2.2 电脑风格 · `desktop`

- **画面**：顶部 macOS 菜单栏 + 窗口（红黄绿点、标题、标签页）+ 左侧导航 + 内容区 + 可选 Dock；内容三种：
  `dashboard`（指标 + 柱图）、`board`（三列看板）、`editor`（代码/编辑器）。
- **版式**：`desktop` 卡通常「上文下窗」，窗口占下半屏；正文 ≤2 行，窗口内不放大段真实数据。
- **适合**：桌面软件、后台、浏览器工具、IDE/工作台；让读者一眼认出「这是电脑上的东西」。
- **诚实**：窗口内数字标「示意」；真实后台截图用 `shot` + 官方素材。

### 2.3 卡片风格 · `bento`

- **画面**：3 列或 4 列网格，格子可 `span2`、`tall`；每格一个信息：图标 + 标题 + 一句说明 + 可选数字/标签。
- **语气**：一块强调色（`tone:"accent"`）+ 一块墨色（`tone:"ink"`）就够，其余留白；不要每格都上色。
- **适合**：能力清单、卖点墙、合集、教程总览；也常作为手机/电脑风格之后的「收束页」。
- **反模板**：格子大小要有理由（重要信息占 2 格），不要 3×3 等分九宫格当装饰；序号只在真是序列时用。

### 2.4 流程图风格 · `flowchart`

- **画面**：936px 宽画布；胶囊起止节点 → 圆角步骤节点 → **菱形判断** → 左右分支 → 汇合 → 结束；SVG 正交连线 + 箭头 + 是/否标签。
- **字段示例**：

```json
{"type":"flowchart","start":"导入仓库","steps":[{"t":"解析结构","d":"模块/依赖"}],
 "decision":{"q":"发现循环依赖？","yes":{"t":"标红","d":"先解耦"},"no":{"t":"出图","d":"四视图"}},
 "end":"导出 PNG / SVG"}
```

- **约束**：步骤 2–4 个；判断 1 个；分支各 1 个；节点文案 ≤10 字，说明 ≤18 字；不要画无出口的环。
- **适合**：流程、审批、教程、决策、SOP；正文配图高度建议 ≥900，避免节点被裁。

### 2.5 产品宣传图 · `promo`

- **画面**：海报级大标题（2 行）+ 产品舞台（手机/电脑/真实截图）+ 聚光圈 + 3 个卖点浮签 + 价格/协议 + 底部卖点条 + 单一 CTA。
- **字段**：`promoBadge`（NEW/2.0）、`hero.device`（phone/desktop）、`hero.price`/`priceNote`、`hero.tags`、`points[]`、`cta`。
- **约束**：一屏只推一个产品/一个价格；卖点 ≤3 条；价格/协议必须真实；没有真实截图时用 `device` 示意并标注。
- **适合**：新品发布、预售、促销、卖点主视觉；也可作为文章封面（`article.cover.hero`）。

### 2.6 文章图文

文章不是「贴图配文」：正文 ≥800 字、≥3 张配图、图和文字交替。画面风格可以进入正文配图：
手机截图讲操作、电脑窗口讲界面、流程图讲判断、Bento 讲能力全景、宣传图讲新品。
骨架见第 3 节，排版见 [article-format](article-format.md)。

### 2.7 二维码 · `qr`（结尾卡 / 宣传卡）

结尾卡与宣传卡的二维码**必须是真实可扫的码**，不再画占位图案。

```json
{ "qr": { "url": "https://github.com/v0/layer", "label": "扫码看源码", "logoText": "L" } }
```

- `url`：必填，官网 / GitHub / 文档地址；`label`：码下小字（默认「扫码打开」）；`logoText`：码中心挖白块并放 1 个字（可选）。
- 也接受简写：`"qr": "https://..."` 直接给地址；`"qr": true` 只是占位（会触发 warn，不推荐）。
- 编码器：`scripts/qr.mjs`（零依赖，移植 qrcode-generator/Kazuhiko Arase MIT 的内核，byte 模式 + RS 纠错 + 掩码自动择优，默认纠错 M）。已用 OpenCV 解码回归验证：结尾卡与宣传卡里的码都能扫出 `<url>`。
- 校验：`check.mjs` 会生成一次二维码，码指向的地址**必须与 `article.links` 中的某条一致**，否则 warn；地址不是 http(s) 直接 fail。
- 尺寸：结尾卡 200px 白底盒（内部 10px 留白，码面约 180px）；宣传卡 132px。不要再把码贴到深色底上——**白底与 4 模块留白是扫码的最低要求**。
- 短链优先：地址超过 40 个字符时提示用短链，版本会升到 v5 以上，码点变密。

## 3. 文章风格库（8 种骨架）

| 骨架 | 标题范式 | 结构（节） | 语气 | 配图 |
|---|---|---|---|---|
| **A · 开源项目推荐（刘哥式）** | 「开源｜一款……，支持……」「又挖到……：1.4 万 Star」 | 痛点场景 → 它是什么 → 核心能力（01/02…）→ 上手 → 边界提醒 → 写在最后+点赞 | 口语、诚实、讲边界、具体数字 | 封面 + 架构/界面图 + 能力图解 + 对比表 |
| **B · 产品发布** | 「……终于来了」「不用再……了」 | 痛点 → 我们做了什么 → 核心能力 → 怎么用（3 步）→ 价格/协议 → CTA | 有力、利益点前置 | 界面主图 + 功能动线 + 对比 |
| **C · 横评对比** | 「A、B、C 怎么选：……横向对比」 | 结论先行 → 对比维度表 → 逐个点评 → 按场景选 → 边界 | 中立、给判断 | 维度矩阵图 + 评分表 |
| **D · 教程一图流** | 「照着点就行：……四步……」「一张图搞懂……」 | 承诺+效果 → 全流程图 → 分步（每步一图+避坑）→ 总清单 → 风险 | 手把手、给模板 | 一图流总览 + 每步截图 |
| **E · 数据复盘** | 「……只做 X，远远不够」 | 反常识结论 → 指标体系图 → 逐指标（定义/阈值）→ 误判 → 行动清单 | 冷静、结构化 | 指标图 + 趋势图 + 表 |
| **F · 口播视频工作流** | 「我用 X 做口播，3 个 Skill 就够了」 | 痛点 → 工作流全图 → 每步工具/参数 → 成品对比 → 边界 | 亲历、可复制 | 工作流图 + 前后对比 |
| **G · 产品宣发** | 「X 2.0 来了：……」「一张图，把……讲清楚」 | 一句卖点 → 产品舞台 → 3 个场景/能力 → 价格/协议 → 上手路径 → 边界 | 有画面感、利益点前置 | 宣传主视觉 + 手机/电脑截图 + 能力墙 |
| **H · 设备图文（手机/电脑）** | 「在手机里，把……」「桌面上的一张……」 | 场景钩子 → 设备截图（示意/真图）→ 3–5 步操作 → 避坑 → 适用边界 | 亲历、像教程 | 手机聊天/信息流 + 桌面窗口 + 流程图 |

**通用硬约束**：正文 ≥800 字（建议 1500–3000），≥3 张配图，「文字介绍 + 图片」交替；小标题结论式且编号统一；
图注固定「图N：一句话」；技术类必写「边界/风险/适用性」；html 全内联。

## 4. 视频号风格库（可选产出 · 3 种）

| 形式 | 时长 | 画面 | 适合 | 产出 |
|---|---|---|---|---|
| **口播干货** | 30–60s | 真人/数字人口播 + 大字幕 + 关键画面 | 观点、工具推荐、避坑 | 口播稿 + 分镜 + 竖版封面 |
| **图文轮播** | 15–40s | 6–9 张竖版卡片轮播（可复用贴图） | 清单、教程、榜单 | 卡片序列 + 转场节奏 + 封面 |
| **屏幕解说** | 45–90s | 录屏 + 旁白 + 局部放大/标注 | 软件演示、操作教学 | 录屏脚本 + 标注点 + 封面 |

## 7. 组合与避坑

1. **一个主画面风格 + 一个辅助版式**：手机/电脑做主视觉，Bento 收能力，流程图讲判断，宣传图做封面；不要五类平权。
2. **主题可以换，骨架别乱换**：`phone` 卡在 `dark` 主题下依然成立，但不要在同一套图里既放手机又放电脑当封面。
3. **示意图要诚实**：设备 UI、窗口数字、价格都要标「示意」或给真实来源；真实截图优先。
4. **图内字号随画布走**：3:4 卡用 76/92 标题，文章配图 56，封面 60；不要把 3:4 的字号直接塞进 460 高封面。
5. **流程图别塞满**：2–4 步 + 1 个判断最舒服；超过 6 个节点拆成两张。
6. **Bento 不要等分九宫格**：用 span/tall 做层级；一块强调色 + 一块墨色足够。
7. **宣传图只推一个东西**：一个产品、一个价格、一个 CTA；卖点条 ≤3 条。
