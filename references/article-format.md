# 文章格式规范（article-format）

公众号「图文消息」长文的排版与结构规范。目标：手机上读着舒服、层次清楚、图和文字互相解释。

## 1. 微信排版参数（正文默认值）

微信编辑器会剥离绝大多数 CSS，只认**内联样式**；比内联样式更关键的是：它还会按**标签白名单**清洗 DOM、丢弃整页外壳。
两条同时满足才算「能粘」。以下为默认参数，样式统一来自 [../scripts/article-tokens.mjs](../scripts/article-tokens.mjs)：

| 元素 | 参数 |
|---|---|
| 正文字号 / 行高 | 16px / 1.75 |
| 字间距 | 0.5px |
| 段间距 | 段落下边距 1.2em（约 19px） |
| 正文颜色 | #3F3F3F（次要 #8A8A8A） |
| 对齐 | 两端对齐；短句可居中 |
| 段长 | 每段 2–4 行（手机屏 ≤5 行），一句话成段也 OK |
| 页边距 | 由微信控制，正文左右各留白即可，不额外加 |

### 各级标题
- **一级小标题（节）**：18–20px，加粗，主题色；前面可加色块/序号，上方留白 2em、下方 1em。编号用「一、二、三」或「01 02 03」二选一并全文统一。
- **二级小标题**：16px 加粗，正文色，可加粗体与一点下划线强调。
- **导语**：15–16px，灰色（#6B6B6B），可放在浅灰底引用块或左竖线块里。

### 强调样式（只用这几种）
- 加粗 + 主题色：关键结论。
- 浅色底高亮（背景 #FFF3D6 或品牌色 8% 透明）：关键词/数字。
- 引用块：左边框 4px 主题色 + 浅灰底 + 内边距 12–16px。
- 分割线：细线（#E5E5E5）或三个小色块的居中分隔。

### 图片
- 宽度 100%，圆角 8–12px，居中，上下外边距 1.5em。
- 图注：13–14px、灰色（#9A9A9A）、居中，格式固定「**图N：一句话说明**」；图注在图下方。
- 图片必须与上下文相关，每图最多讲一件事；连续两张图之间要有文字过渡。
- 每篇正文**至少 3 张配图**（1 张总览/介绍图 + 若干图解或截图），做到「文字介绍 + 图片」交替，避免整屏纯文字。
- 设备类配图（手机 404×820、桌面窗口 936 宽、流程图 936 宽）在 1080 宽画布里优先给足高度：**手机/电脑图 ≥900，流程图 ≥900**，否则设备会被裁。
- 配图内不放大段正文；手机屏为示意 UI 时，图注写「图N：…（示意）」，真实截图优先。

### 表格
- 斑马纹（隔行浅灰），表头主题色底 + 白字，圆角边框；列数 ≤4，移动端不横向溢出（超 4 列改成分条列表）。

### 链接与代码
- 外链在文末「项目地址 / 参考」集中列，正文少放裸链（微信正文外链不可点，用「阅读原文」或文末）。
- 代码用等宽字体 + 深色底引用块，行数 ≤12，长代码截断并说明。

### 封面
- 首图/封面用 **2.35:1（1080×460）**；信息流缩略另出 **1:1（1080×1080）** 方版——两版都要出，缺一不可。
- 封面要在 3 秒内让人看懂主题（大标题 + 一个视觉锚点）。
- 正文顶部可放同一张封面作**题图**（可选，`article.headerImage`），标题下方先给一张图再进导语。

## 2. 文章结构（默认骨架）

1. **顶部条**（可选）：公众号定位/栏目条，一句「每天推荐一个最值得用的 X」。
2. **标题**：取标题备选中推荐的一条。
3. **摘要**：≤54 字，独立成立，用于分享卡片。
4. **导语**：3–5 句。钩子＝痛点 / 反常识结论 / 一个具体数字 / 亲历场景。先说结论或冲突，别铺垫。
5. **正文分节**：3–5 节，每节「小标题 + 段落 +（配图/表格/引用/清单）」。
6. **收尾**：总结一句 + 边界/风险/适用性声明（技术类必写「边界」）。
7. **CTA / 项目地址 / 相关阅读**。
8. **署名/作者行**（可选）。

字数：一般 1500–4000 字；教程与复盘可到 5000；项目推荐 1200–2500 为宜。**硬性下限：正文 ≥800 字**——短于 800 字只能算「贴图配文」，不能当文章发布。

## 4. Markdown 正文骨架

    # 标题（推荐那条）

    （导语：3–5 句，钩子打头）

    段落……

    参考：...

## 5. 可粘贴 HTML 规则（交给微信编辑器）

**这一节是硬规则，check.mjs 会卡。** 目标：article.html 打开就是一段能直接粘的片段，粘过去后「看着一样」。

### 5.1 结构：只输出片段，不输出整页

- article.html **只含一个根 `<section>`**，不写 `<!doctype>`、`<html>`、`<head>`、`<title>`、`<body>`。
  整页文档会在粘贴时把 head/body 的样式一起打包，编辑器按「整页网页」处理，结果往往是空、纯文本或样式全丢。
- 根节点**不写** `max-width`、`margin:0 auto`、`padding` 居中容器——微信不保留，还会挤压正文宽度。
- 本地要看效果，用 `article-preview.html`（带整页外壳的预览页）；**复制粘贴用 article.html，不要用预览页**。

### 5.2 标签：只用白名单

| 需要的东西 | 不要用 | 改成 |
|---|---|---|
| 大标题 / 小节标题 | `<h1>` `<h2>` | `<p><strong …></strong></p>` |
| 图片 + 图注 | `<figure><figcaption>` | `<p><img></p>` + `<p>图N：…</p>` |
| 引用块 | `<blockquote>` | 带左边框的 `<p>` |
| 分割线 | `<hr>` | `<p style="margin:28px 0;height:1px;border-top:1px solid #E5E7EB"></p>` |
| 表格 | `<table>` | 表头加粗段落 + `· 列名：值` 分条段落 |
| 容器 | `<div>` | `<section>` |
| 列表 | `<ul><li>` | `· ` + `<p>` |

白名单：`section / p / span / strong / b / em / i / img / br`。

### 5.3 样式：只写会被保留的属性

- 保留：`color`、`font-size`、`font-weight`、`line-height`、`margin`、`padding`、`background`、`border`、`border-radius`、`text-align`、`width`。
- **会被清理，写了也不生效**：`font-family`、`letter-spacing`、`max-width`、`margin:0 auto`、`position`、`display:flex/grid`、CSS 变量。
- 不写 `<style>`、`<script>`、外链字体与外部样式表。
- 图片：`<img style="width:100%;height:auto;display:block"`，不加圆角（配图 PNG 自带画布）。

### 5.4 图片：必须手动上传

- HTML 里的图是**占位**：`src="images/figN.png"` 是相对路径，粘贴后一定裂图（编辑器没有基准目录）。
- 正确顺序：先粘文字，再按图注顺序用编辑器「图片」按钮上传 `article/images/fig1..N`。
- 封面不进正文：`cover.png`（2.35:1）用编辑器设封面，`cover-square.png` 备 1:1 分享图。

### 5.5 粘贴操作（最容易翻车的一步）

**判断贴没贴对**：如果编辑器里出现一串 `<section style="...">`、`<p style=...>` 这样的**标签源码**，说明粘进去的是**纯文本**，不是富文本——这是最常见的失败，产出的 HTML 没问题，问题在剪贴板的来源。

> 平台提醒：macOS 官方微信客户端会把 HTML 富文本剪贴板**二次转换**成样式更少的版本；遇到「顶部条/目录框底色、圆角、浅灰图注样式丢了」，不是文件的问题。此时改用**微信公众平台网页版编辑器**粘贴，或把结构改为「纯文字 + 图片」的极简版。

推荐做法（跨平台通用）：

1. 浏览器打开 **article-import.html**，核对排版；
2. 点顶部「**复制全文**」按钮（复制的是渲染后的富文本）；
3. 到公众号编辑器正文区 Ctrl+V / Cmd+V。

备选与禁止：

- macOS：VS Code 等**富文本编辑器**打开 article.html 全选复制，也可以。
- **禁止**用记事本（Windows）/ TextEdit 纯文本模式（macOS）/ Notepad++ / Sublime 等**纯文本编辑器**打开复制：剪贴板里只有文本，粘过去就是源码。
- **不要**在浏览器里打开 article.html 后整页全选复制：会连带整页外壳一起复制，样式反而容易乱（导入页没有这个问题，因为它的内容区只含片段）。

每次粘贴后核对：小标题蓝色加粗、图注在图下方、分割线留白、列表逐条分行。

### 5.6 产出文件

| 文件 | 用途 |
|---|---|
| article.html | **粘贴用片段**（只有根 section），源码 |
| article-import.html | **浏览器打开、点「复制全文」**的导入页（富文本剪贴板，跨平台可用） |
| article-preview.html | 本地预览页（含整页外壳），只看不复制 |
| article.md | Markdown 源，与 HTML 同源同内容 |
| 粘贴说明.md | 本次产物的粘贴步骤 + 逐项核对清单 |

正文中不要出现 Markdown 语法残留（`** **`、`##` 等），HTML 版要渲染后的样子。

## 6. 参考文章骨架（来自 15 篇实战）

### 6.1 「开源项目推荐」长文（最常用）
```
标题：开源｜一款……，支持……（结果钩子 + 具体能力，≤30 字）
开头段（2–3 句）：还原一个接私活 / 接手陌生项目 / 装插件的真实场景，点出痛点。
（可选）先给结论：一句话它是什么 + 一个数字（Star / 协议 / 版本）。
## 01 它是什么
  - 定位一句话；技术栈/协议/Star；仓库与在线地址。
## 02 核心能力（3–5 点，每点一个小标题或加粗行）
  - 每点：能力名 + 一句人话解释 + 一个使用场景。
## 03 怎么用（3 步上手）
## 04 技术栈 / 参数（用表格，≤4 列）
## 05 必须说清楚的边界（成熟度、适用/不适用、坑）
## 写在最后
  - 一句价值总结 + 一个主 CTA（点个赞 / 分享给…… / 回复关键词）。
```

### 6.2 「横评对比」长文
结论先行（谁适合谁）→ 对比维度表（形态/语言/许可/场景）→ 逐个点评（各 1 段）→ 按场景选 → 边界。

### 6.3 「数据复盘」长文
一个反常识结论打头 → 指标体系图 → 每个指标「定义 + 怎么看 + 阈值」→ 常见误判 → 行动清单。

### 6.4 「产品宣发」长文（G）
```
标题：X 2.0 来了：一句话把卖点说清（≤30 字）
开头：先给画面/结果，再给一句价值（3–4 句）
## 01 它解决什么问题（一个具体场景）
## 02 产品全景（宣传主视觉 + 3 个能力）
## 03 三个使用场景（手机 / 桌面 / 团队协作，各 1 段）
## 04 价格 / 协议 / 上手路径（表格 ≤4 列）
## 05 边界与不适合的人（诚实提醒）
写在最后：一句价值 + 一个 CTA
```

### 6.5 「设备图文」长文（H）
```
标题：在手机里，把…… / 桌面上的一张……
开头：还原「你正在用手机/电脑处理这件事」的场景
## 01 先看结果（一张设备截图）
## 02 操作步骤（3–5 步，每步一图 + 一句要点）
## 03 它为什么这样设计（流程图或对比）
## 04 避坑与限制（哪些事它做不了）
## 05 适合谁 / 不适合谁
写在最后：一个主 CTA
```

### 6.6 通用强化（从参考里学到的）
- **编号用 01 / 02 / 03**（比「一、二、三」更现代，全文统一）。
- **能列表就列表**：能力用 `•` / 短行；参数用表格；对比用两列表。
- **短段落**：一句话一段很常见，手机上更好读；每段 ≤4 行。
- **结尾必有「写在最后」+ 单一 CTA**（点赞/分享/关注三选一），不要堆五个。
- **诚实提醒单独成节**：边界/风险/不适用，是参考文章信任感的来源。
- 封面：1080×460（2.35:1）+ 1080×1080（1:1）；正文首图可用同一张题图。
